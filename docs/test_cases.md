# Тест-кейсы бэкенда VKR
## Общие условия

- Бэкенд запущен и подключён к изолированной тестовой PostgreSQL.
- На сервере задан непустой `VK_SECRET_KEY`, совпадающий с секретом в настройках Callback API тестового сообщества VK. 
- Настроен действующий токен сообщества. Тестовые сотрудники разрешили сообщения сообщества, диалоги с ботом открыты.
- POST-запросы из Postman: `Content-Type: application/json`, `base_url` по умолчанию — `http://127.0.0.1:8000`.

## TC-01. Отклик на смену с неверным секретным ключом
### Предусловия

1. Выполнены общие условия.
2. Создана запланированная смена на будущую дату с одним свободным местом на должность «Продавец».
3. В организации смены есть активный сотрудник с должностью «Продавец» и привязанным VK ID.
4. Сотрудник не назначен на смену.

### Тестовые данные

| Параметр | Значение |
|---|---|
| `base_url` | `http://127.0.0.1:800` |
| Ключ на сервере | Фактический непустой `VK_SECRET_KEY` |
| Ключ в запросе | `qa_wrong_secret`, отличающийся от ключа сервера |
| `shift_id` | ID подготовленной смены |
| `vk_user_id` | VK ID подготовленного сотрудника |
| `vk_group_id` | Числовой ID тестового сообщества |
| Должность | `Продавец` |

### Запрос

**POST** `{{base_url}}/vk/callback`

```json
{
  "type": "message_event",
  "group_id": {{vk_group_id}},
  "secret": "qa_wrong_secret",
  "object": {
    "user_id": {{vk_user_id}},
    "peer_id": {{vk_user_id}},
    "event_id": "tc01-invalid-secret-001",
    "conversation_message_id": 1,
    "payload": {
      "type": "shift_response",
      "shift_id": {{shift_id}},
      "position": "Продавец"
    }
  }
}
```
### Шаги и ожидаемые результаты

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Зафиксировать исходные записи смены в `shift_assignments`, `shift_open_positions`, `shift_responses` и `activity_logs` | Назначение сотрудника отсутствует; доступно одно место. Исходное состояние сохранено для сравнения |
| 2 | Отправить запрос | HTTP `403`; JSON-ответ `{"detail":"Invalid VK secret key"}` |
| 3 | Сопоставить состояние четырёх таблиц с исходным | Назначение не создано; место не израсходовано; новые записи отклика и действия отсутствуют |
| 4 | Открыть диалог сотрудника с сообществом | Новых сообщений, вызванных этим запросом, нет |

### Постусловия
Состояние смены, назначений и истории не изменилось.

## TC-02. Отклик на смену с пустым полем position
### Предусловия

1. Выполнены общие условия.
2. Создана запланированная смена на будущую дату с одним свободным местом на должность «Продавец».
3. В организации смены есть активный сотрудник с должностью «Продавец» и привязанным VK ID.
4. Сотрудник не назначен на смену. Должностей с пустым названием нет.

### Тестовые данные

| Параметр | Значение |
|---|---|
| `base_url` | `http://127.0.0.1:800` |
| `secret` | `{{vk_secret}}` — правильный ключ сервера |
| `shift_id` | ID подготовленной смены |
| `vk_user_id` | VK ID подготовленного сотрудника |
| `vk_group_id` | Числовой ID тестового сообщества |
| `position` в запросе | Пустая строка `""` |

### Запрос

**POST** `{{base_url}}/vk/callback`

```json
{
  "type": "message_event",
  "group_id": {{vk_group_id}},
  "secret": "{{vk_secret}}",
  "object": {
    "user_id": {{vk_user_id}},
    "payload": {
      "type": "shift_response",
      "shift_id": {{shift_id}},
      "position": ""
    }
  }
}
```

### Шаги и ожидаемые результаты

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Зафиксировать исходные назначения, свободные места и ID откликов смены | Сотрудник не назначен; по должности «Продавец» доступно одно место. Исходные ID откликов сохранены |
| 2 | Отправить запрос | HTTP `200`; тело ответа — `ok` |
| 3 | Сопоставить назначения и свободные места с исходным состоянием | Назначение не создано; свободное место по должности «Продавец» сохранено |
| 4 | Найти новую запись в `shift_responses` по смене, VK ID, времени запроса и отличию от исходных ID | Создана одна запись для выбранной смены и сотрудника: `position_name = ""`, `response_status = "rejected"`, `response_message = "Должность сотрудника не подходит для этой позиции"` |

### Постусловия

Сотрудник не назначен, свободное место сохранено. В истории зарегистрирован отклонённый отклик.

## TC-03. Успешный отклик первого сотрудника на последнее свободное место
### Предусловия

1. Выполнены общие условия.
2. Создана запланированная смена на будущую дату, время `09:00–18:00`.
3. В `shift_open_positions` есть одна позиция «Продавец» с `employee_count = 1`, почасовой оплатой 500 ₽/ч.
4. В организации смены есть активный сотрудник с должностью «Продавец» и привязанным VK ID.
5. Сотрудник не назначен на эту смену.
6. Сотруднику отправлено уведомление именно об этой смене; в диалоге доступна кнопка «Хочу выйти: Продавец».

### Тестовые данные

| Параметр | Значение |
|---|---|
| `base_url` | `http://127.0.0.1:800` |
| `shift_id` | ID подготовленной смены |
| `employee_id` | Внутренний ID подготовленного сотрудника в БД |
| `vk_user_id` | VK ID этого сотрудника |
| Должность | `Продавец` |
| Ставка | 500 ₽/ч |

### Шаги и ожидаемые результаты

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Зафиксировать исходные назначения, свободную позицию и её поля оплаты | Назначение сотрудника отсутствует; доступно одно место. Значения `payment_type`, `hourly_rate`, `fixed_rate`, `percent_rate` сохранены для сравнения |
| 2 | Зафиксировать время и один раз нажать «Хочу выйти: Продавец» в уведомлении подготовленной смены | VK показывает «Сотрудник назначен на свободную позицию»; в диалог поступает список смен с новой сменой |
| 3 | Получить назначения смены из `shift_assignments` | Создано ровно одно назначение для `employee_id` на должность «Продавец»; поля оплаты совпадают с исходной свободной позицией, `hourly_rate = 500` |
| 4 | Получить свободные позиции этой смены из `shift_open_positions` | Строка занятой позиции удалена, свободных мест на должность «Продавец» нет |
| 5 | Найти новый отклик по смене, сотруднику и времени нажатия, а также новое действие смены в `activity_logs` | Создан один отклик `accepted` с сообщением «Сотрудник назначен на свободную позицию» и запись действия `vk_response`. Зафиксировать ID отклика |
| 6 | Отправить `GET {{base_url}}/api/shift-responses` | HTTP `200`; в JSON-массиве `responses` есть запись с зафиксированным ID, правильными сменой, сотрудником, должностью и `response_status = "accepted"` |
| 7 | Найти обращение `POST /vk/callback` за время нажатия в журнале Uvicorn | Обработка запроса завершилась с HTTP `200` |

### Постусловия

Сотрудник назначен на смену, последнее место занято. Успешный отклик сохранён в БД и доступен через API истории.

## TC-04. Рассылка уведомления двум сотрудникам об одном свободном месте
### Предусловия

1. Выполнены общие условия.
2. Создана запланированная смена на будущую дату с одним свободным местом на должность «Продавец».
3. В организации смены есть два активных сотрудника с должностью «Продавец» и разными VK ID.
4. Оба сотрудника не назначены на смену.
5. Доступны оба тестовых VK-аккаунта; перед отправкой зафиксированы последние сообщения в их диалогах с сообществом.

### Тестовые данные

| Параметр | Значение |
|---|---|
| `base_url` | `http://127.0.0.1:800` |
| `shift_id` | ID подготовленной смены |
| `vk_user_id_1` | VK ID первого сотрудника |
| `vk_user_id_2` | VK ID второго сотрудника |
| Текст | `Открыта смена для продавца. Доступно одно место.` |
| Должность | `Продавец` |
| Количество мест | `1` |

### Запрос

**POST** `{{base_url}}/api/send-shift-notification`

```json
{
  "shift_id": {{shift_id}},
  "message": "Открыта смена для продавца. Доступно одно место.",
  "user_ids": [{{vk_user_id_1}}, {{vk_user_id_2}}],
  "open_positions": [
    {
      "position": "Продавец",
      "count": 1
    }
  ]
}
```

### Шаги и ожидаемые результаты

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Зафиксировать исходные назначения, свободные места и записи `sent_notifications` для смены | Назначений нет; доступно одно место. Исходные записи уведомлений сохранены для сравнения |
| 2 | Отправить запрос | HTTP `200`; JSON содержит массив `results` из двух элементов. Для каждого переданного `user_id`: `status = "sent"`, `error = ""` |
| 3 | Открыть диалоги обоих сотрудников с сообществом | В каждом появилось ровно одно новое уведомление с точным текстом из запроса |
| 4 | Осмотреть кнопки в обоих новых уведомлениях, не нажимая их | В каждом уведомлении одна кнопка «Хочу выйти: Продавец» |
| 5 | Получить новые записи `sent_notifications` для смены | Добавлено ровно две записи, по одной на каждого получателя. Правильные `shift_id`, `user_id`, `message_text`; `send_status = "sent"`, `error_text = ""` |
| 6 | Сопоставить назначения и свободные места с исходным состоянием | Назначения не созданы; по должности «Продавец» осталось одно свободное место |

## TC-05. Отклик второго сотрудника на уже занятое место
### Предусловия

1. Выполнены общие условия.
2. Создана запланированная смена на будущую дату, в которой исходно было одно место на должность «Продавец».
3. В организации смены есть два активных сотрудника с должностью «Продавец» и разными VK ID.
4. Первый сотрудник уже назначен на это место. В `shift_open_positions` нет строки этой смены с должностью «Продавец».
5. Второй сотрудник не назначен на смену. До занятия места ему отправлено уведомление об этой смене; в его диалоге сохранилась активная кнопка «Хочу выйти: Продавец».
6. Исходное назначение подготовлено отдельно; выполнение TC-03 не требуется.

### Тестовые данные

| Параметр | Значение |
|---|---|
| `base_url` | `http://127.0.0.1:800` |
| `shift_id` | ID подготовленной смены |
| `employee_id_1` | Внутренний ID назначенного сотрудника |
| `employee_id_2` | Внутренний ID второго сотрудника |
| `vk_user_id_2` | VK ID второго сотрудника |
| Должность | `Продавец` |


### Шаги и ожидаемые результаты

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Зафиксировать назначение первого сотрудника и свободные позиции смены | Существует одно назначение для `employee_id_1`; свободных мест по должности «Продавец» нет |
| 2 | Зафиксировать время и из аккаунта второго сотрудника один раз нажать «Хочу выйти: Продавец» в ранее полученном уведомлении | VK показывает «Свободных мест по этой позиции уже нет» |
| 3 | Сопоставить назначения и свободные позиции с исходным состоянием | Назначение для `employee_id_2` отсутствует; назначение первого сотрудника не изменено; свободные места не появились |
| 4 | Найти новый отклик по смене, второму сотруднику и времени нажатия | Создан один отклик второго сотрудника: `response_status = "rejected"`, `response_message = "Свободных мест по этой позиции уже нет"`. Зафиксировать ID отклика |
| 5 | Отправить `GET {{base_url}}/api/shift-responses` | HTTP `200`; в массиве `responses` присутствует запись с зафиксированным ID, правильными сменой и вторым сотрудником, статусом `rejected` и сообщением об отсутствии мест |
| 6 | Найти обращение `POST /vk/callback` за время нажатия в журнале Uvicorn | Обработка запроса завершилась с HTTP `200` |

### Постусловия

Первое назначение сохранено, второе не создано. Отказ зарегистрирован в истории и доступен через API.
